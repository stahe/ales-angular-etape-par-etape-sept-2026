    11. Despliegue

    En desarrollo, dos servidores trabajan juntos: el servidor de desarrollo de [Angular] (el cliente) y el servidor JSON (la API). En producción, solo hay uno:

    1. Compile el cliente. En la carpeta [rdvmedecins-angular]:

    npm run build

    La carpeta [dist/rdvmedecins-angular/browser/] contiene toda la aplicación: una página [index.html], una hoja de estilo y archivos [JavaScript] optimizados (el código de [Angular], el enrutador, [ngx-translate]... y el nuestro):

    • Los archivos iniciales se descargan al inicio: aproximadamente 135 KB una vez comprimidos por el servidor;
    • cada página cargada bajo demanda ([loadComponent]) tiene su propio archivo, que se descarga en la primera visita;
    • el nombre de cada archivo contiene un hash de su contenido ([main-3NXKYGU5.js]): una nueva versión tendrá un nombre distinto, y un navegador nunca podrá almacenar en caché una versión obsoleta;
    • el compilador ha verificado los presupuestos (budgets) definidos en [angular.json]: una advertencia indicaría que una aplicación se ha vuelto demasiado grande.

    2. Cárguela en el servidor. Copie el CONTENIDO de la carpeta [dist/rdvmedecins-angular/browser/] en una carpeta [client/] en la raíz del servidor JSON ([rdvmedecins-nestjs-json/client/index.html], [rdvmedecins-nestjs-json/client/main-3NXKYGU5.js]...) y luego reinicie el servidor. Este muestra:

[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    La aplicación completa ya está disponible en http://localhost:8080. El servidor sirve los archivos del cliente y devuelve [index.html] para cualquier otra URL fuera de /api: recargar la página /schedule funciona (es el navegador del cliente el que la muestra). Para el lector curioso, es el archivo [src/web/client-spa.ts] del servidor el que realiza esta tarea.

    3. En un entorno de producción real, no olvide el archivo [.env] en el servidor:

    • un [JWT_SECRET] largo y aleatorio;
    • un [CAPTCHA_TEST] vacío;
    • [COOKIE_SECURE=true] si el sitio se sirve mediante HTTPS (debe hacerse así: se transmiten contraseñas);
    • [TRUST_PROXY=true] si el servidor está detrás de un proxy ([nginx]...), para que el límite de intentos vea la dirección IP real de los clientes.

    Luego se inicia el servidor compilado: [npm run build], seguido de [npm run start:prod].
