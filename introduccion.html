    Este documento es un producto de Claude, la IA de Anthropic. Continúa el curso “Introducción paso a paso al framework web NestJS”, desde el cual cambia la perspectiva:

    • en el curso [NestJS], el servidor genera las páginas HTML (motor de vistas [Handlebars]); el navegador se limita a mostrarlas;
    • en este curso, las páginas se generan en el navegador mediante una aplicación [Angular]; el servidor, ahora reducido a un simple servidor JSON, solo proporciona datos.

    Sin embargo, las páginas de la aplicación permanecen sin cambios: son las de la aplicación [RdvMedecins] ya presentada con los otros frameworks (inicio de sesión con CAPTCHA, agenda del médico, ventana de citas, portal del paciente, gestión de médicos y clientes, creación de cuentas, francés e inglés).

    Este documento sigue la misma estructura que sus predecesores: primero, numerosos ejemplos breves, cada uno centrado en un concepto específico de [Angular], seguidos de un caso de estudio completo (el cliente [Angular] de la aplicación [RdvMedecins]) con todos los archivos anotados. Sigue el esquema del curso “Introducción paso a paso al framework Vue.js”: los lectores familiarizados con [Vue.js] encontrarán los mismos ejemplos, escritos al estilo de [Angular]. Dado que [Angular] es un framework con más funcionalidades, hay más ejemplos: 25 en lugar de 20.

    Ya existe un curso sobre este tema: Un ejemplo cliente/servidor con Angular/NestJS (2026), que cubre tanto el servidor como el cliente. Este documento difiere en su enfoque: el servidor se trata como una caja negra, de la cual solo nos interesan la API y el JSON, y aprendemos [Angular] paso a paso antes de abordar el cliente completo.

    1.1. El papel de Angular en una aplicación web

    La aplicación tiene dos partes, que se comunican entre sí únicamente mediante solicitudes:

    • 1: La aplicación [Angular], que se ejecuta en el navegador, envía una solicitud HTTP al servidor, por ejemplo, [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: El servidor responde con datos JSON: la agenda de ese médico para ese día. No genera ninguna página;
    • 3: Con estos datos, [Angular] actualiza la página mostrada en el navegador sin recargarla.

    El siguiente diagrama compara las dos arquitecturas:

    El navegador carga una sola página HTML casi vacía al iniciar. Todo lo demás lo genera el código [JavaScript]: esto se conoce como aplicación de página única (SPA, por [Single Page Application]). Cuando el usuario hace clic en un enlace interno, no se solicita ninguna página al servidor: el enrutador de [Angular] cambia la URL mostrada y reemplaza el contenido de la página.

    [Angular] es un framework creado por Google. Su primera versión, [AngularJS] (2010), fue reescrita por completo en 2016: es esta reescritura, en [TypeScript], la que ahora se denomina simplemente [Angular], y que publica una nueva versión mayor cada seis meses. Se basa en tres ideas:

    • componentes: la interfaz se descompone en piezas reutilizables (una barra de navegación, un campo de formulario, una ventana de confirmación, etc.). Un componente es una clase [TypeScript] asociada a una plantilla HTML y a un estilo CSS;
    • Reactividad, basada en señales: los datos de un componente se almacenan en señales. Cuando una de ellas cambia, [Angular] actualiza automáticamente las partes de la página que la muestran. Nunca escribimos código que modifique directamente la página;
    • Inyección de dependencias: los componentes no crean por sí mismos los objetos que necesitan (acceso al servidor, usuario conectado, idioma, etc.); los solicitan, y [Angular] los proporciona. Este es el mecanismo que el curso [NestJS] ya presentó en el lado del servidor; de hecho, [NestJS] se inspiró en él.

    A diferencia de [Vue.js], [Angular] es un framework “todo en uno”: el enrutador, los formularios, el cliente HTTP, las animaciones y las pruebas son proporcionados por el propio equipo de [Angular], junto con pautas de uso recomendadas.

    Usaremos [Angular] 22, con sus funcionalidades más recientes: componentes independientes ([standalone]), señales, nueva sintaxis de plantillas ([@if], [@for]), formularios basados en señales y detección de cambios sin [zone.js] ([zoneless]), que es el comportamiento predeterminado en [Angular] 22.

    1.2. Herramientas utilizadas

    Los ejemplos se escribieron y probaron con las siguientes herramientas (su instalación se describe en el apéndice):

    • [Node.js] 24 (o al menos 22.22.3: este es el requisito de [Angular] 22) y su administrador de paquetes [npm];
    • el editor [Visual Studio Code], con la extensión [Angular Language Service];
    • un navegador reciente ([Chrome], [Firefox], [Edge]), si es posible con la extensión [Angular DevTools];
    • la herramienta de línea de comandos [curl], que muestra las respuestas HTTP sin procesar;
    • el DBMS [MySQL] (o [MariaDB]), por ejemplo, el de [Laragon] en [Windows]: es necesario para el servidor JSON, como se describe en el capítulo que lo presenta.

    Las bibliotecas son las de los archivos [package.json]: [Angular] 22.2 (el núcleo, el enrutador, los formularios, el cliente HTTP), la herramienta de línea de comandos [Angular CLI] (comando [ng]), [RxJS] 7.8 (observables), [ngx-translate] 18 (idiomas), [TypeScript] 6.0, [Bootstrap] 5.3.

    Instale las bibliotecas una sola vez, en una consola abierta en la carpeta [examples-angular] (en [VS Code]: menú Terminal / Nuevo terminal):

    npm install

    Luego ejecute un ejemplo escribiendo su nombre:

    npm start 01-first-application

    El servidor de desarrollo de [Angular] compila el ejemplo y lo sirve en el puerto 4200: ábralo en http://localhost:4200/. Este servidor no necesita reiniciarse cuando se modifica un archivo: cada archivo guardado se recompila de inmediato y la página del navegador se actualiza automáticamente. Deténgalo con [Ctrl-C] en la consola antes de ejecutar el siguiente ejemplo (solo un ejemplo a la vez puede ocupar el puerto 4200).

    Los ejemplos 22 a 25 consultan el servidor JSON de [RdvMedecins]: deberá tenerlo instalado y en ejecución, como se explica en el capítulo dedicado a él.
